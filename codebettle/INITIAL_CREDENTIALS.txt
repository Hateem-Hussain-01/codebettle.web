FIRST-RUN ADMIN SETUP (implemented in Phase 2, still current)
---------------------------------------------
The official admin accounts do NOT exist until each admin claims theirs:
  1. After the database is connected (DATABASE_URL) and the seed is run,
     open http://localhost:3000/auth/setup (or the deployed URL + /auth/setup).
  2. Pick your admin identity (Hateem Hussain or Ahmad Hassan) and choose
     a password (min 8 characters). The password is hashed with bcrypt
     before it is stored. It is never written to a file, chat or email.
  3. The same flow is available as POST /api/auth/setup (GET returns which
     accounts are already claimed). Once both accounts exist, setup is
     closed and /auth/setup redirects to the sign-in page.
  4. Until the setup runs, there is no official admin login.

HOW TO SIGN IN (development)
----------------------------
  1. Start the app: npm run dev (from the codebettle/ folder).
  2. Official admins: use /auth/setup first (above), then sign in at
     http://localhost:3000/auth/login
  3. Test users: register a new student account at /auth/register, or
     have an admin create one via the Admin Students page / API.
  4. Seeded accounts cannot be signed into (see above).

HOW TO CHANGE A PASSWORD
------------------------
  - Any signed-in user: use the Change Password action (account settings),
    which requires the current password and signs out all other sessions.
  - Official admins: use the password-reset flow once email is configured
    (Resend + domain pending — see RUNBOOK.md). Never ask anyone for a
    password in chat.

SECURITY NOTES
------------
  - The one-click demo login buttons have been removed from the login page.
  - Sessions are server-side (Postgres Session table): signing out,
    suspension, or a password change ends sessions immediately.
  - After 5 failed sign-in attempts for one email address (per IP), sign-in
    is blocked for 15 minutes.
  - Do not commit real passwords, API keys or .env.local to GitHub.
